Sangam Privacy Policy

Last updated: [DATE]  ·  Applies to: Sangam for Android and Sangam for Windows

Sangam is a private messenger built in India. This page explains what we collect, why, and the choices you have. Contact: [YOUR SUPPORT EMAIL]

What we collect

  • Account details: your email address, username, display name, profile photo and status text. We do not ask for your phone number.
  • Messages and media: encrypted payloads for messages, photos, videos, documents and voice notes you send, and call signalling data, so they can be delivered to your recipients' devices.
  • Device information: a device identifier and public Signal Protocol keys (identity key, signed prekey and one-time prekeys) for each device you sign in on, and a push-notification token on Android.
  • Technical data: basic server logs such as timestamps and IP address (including hashed IP counters for login rate limiting), used for security and reliability.

Username check and username sign-in

During sign-up, the app calls the username_available database function to check whether a username is free (returning only true or false). When you sign in using a username instead of an email address, the app calls the rate-limited login-lookup Edge Function (limited to 10 requests per 10 minutes per IP address). By design, username sign-in reveals whether a username exists and resolves it to the account's email address to complete authentication.

How your messages are protected

Signal Protocol Sessions & AES-256-GCM: Messages are encrypted per recipient device using Signal Protocol sessions (Curve25519 / XEdDSA / X3DH / Double Ratchet) over TLS before upload, and a database trigger (trg_messages_strip_companion) strips any legacy companion suffix on insert or update. Photos, voice notes and documents are encrypted client-side with AES-256-GCM before upload, and QR device-pairing and cloud backup blobs are encrypted with PBKDF2-HMAC-SHA256 (120,000 iterations) + AES-256-GCM. The Windows desktop client uses an in-repository JavaScript Signal Protocol implementation that has not been independently audited.

Where data is stored

Backend data is hosted on Supabase over TLS. Private keys and Signal session states on Android are stored in Android EncryptedSharedPreferences, and on Windows are stored using the Windows Data Protection API (DPAPI) via Electron safeStorage.

How we use data

Only to operate Sangam: deliver messages and calls, show your profile to people you chat with, send push notifications, keep accounts secure and prevent abuse. We do not sell your data, show ads, or use your messages to train AI models.

Sharing

We share data only with infrastructure providers needed to operate Sangam (Supabase for database and object storage; Google Firebase Cloud Messaging for Android wake-up notifications) or when required by applicable law.

Retention and deletion

You can delete your account at any time in the app (Settings / Menu → Delete my account). Calling the delete-account Edge Function performs the following actions and verifies each step before removing your login:

  • Storage buckets: deletes your avatar and sync blobs in avatars and your uploaded encrypted media files in message-images.
  • Messages: deletes all rows in public.messages where you are either the sender (sender_id) or the recipient (recipient_id). This removes both messages you sent to others and messages others sent to you from the server database; copies already decrypted and cached locally on another user's device remain on that device only.
  • Groups: for any group you created (public.chat_groups), if other members remain, leadership is transferred to the oldest co-leader (or else the oldest remaining member) and your membership row in public.group_members is removed while preserving the group for remaining members; if no other members remain, the empty group and its messages are deleted.
  • Account & device records: deletes your rows in public.call_chunks, public.calls, public.devices, public.prekey_bundles, public.backups, public.abuse_reports, public.desktop_pairings, and public.profiles, and then deletes your auth.users record once profile deletion succeeds.

Disappearing-message timers are enforced by the client.
